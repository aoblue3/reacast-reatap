# pcwmp連動リアクション機能(ReaCast / ReaTap)

仕様書 v0.4 に基づく実装(プロトタイプ)。PeerCast配信の視聴者がpcwmpの近くに出るリアクションバーから絵文字を送ると、配信者のメインモニターにアニメーション表示される機能一式です。

配信者アプリ・視聴者アプリの正式名称は **ReaCast(配信者アプリ)/ ReaTap(視聴者アプリ)** です(頭文字を揃えつつ、Cast=配信、Tap=タップして押す、で見分けやすくしてあります)。

初めて触る方は、まず [`使い方ガイド.md`](./使い方ガイド.md) を読んでください(配信者・視聴者それぞれの使い方をまとめてあります)。

## 構成

```
relay-server/           中継サーバー(Node.js製、WebSocket)。配信者ごとに「部屋」を持つ。両方のアプリから共通で使う

broadcaster-app-tauri/  ReaCast(配信者アプリ、Tauri製)。実行ファイルが数MB程度と非常に軽い
viewer-app-tauri/       ReaTap(視聴者アプリ、Tauri製)。pcwmpを自動検出し、リアクションバーを追従表示する
```

以前あったElectron版(`broadcaster-app/` / `viewer-app/`)は使わなくなったため廃止しました。今後はこのTauri版(`broadcaster-app-tauri/` / `viewer-app-tauri/`)だけを使ってください。

実行ファイルはTauri(Windowsに元々入っているWebView2を使う仕組み)で作っているため、サイズは1つあたり約9〜14MB程度です。ソース一式をこうして公開しているのも、「知らない相手から届いたexeを黙って実行する」不安をなくし、誰でも同じソースからビルドして中身を確認できるようにするためです。

**Windows実機でのビルド・テスト手順は [`WINDOWSでのテスト手順.md`](./WINDOWSでのテスト手順.md) を参照してください。**

## このセッションで実際に確認できたこと / できなかったこと

このプロジェクトはLinuxのサンドボックス環境で開発しました。以下は実際に自動テスト・実機相当の検証を行って確認済みです。

- 設定ファイルの保存・再読み込み
- 中継サーバーの部屋管理・トークン認証・連打レート制限・再接続
- pcwmp判定ロジック(実行ファイルパスでの一致判定に加え、Tauri版はWin32のウィンドウクラス名`TpcwmpMain`による判定も追加。どちらか一致すれば検出成功)
- **配信者アプリと視聴者アプリを実際に2プロセスとして起動し、Xvfb(仮想ディスプレイ)上で本物の中継サーバーを介して実際にリアクションを送受信し、配信者側のオーバーレイに絵文字が表示されることをスクリーンショットで確認済み。**
- **視聴者アプリの複数配信者同時接続(プロファイルの追加・接続・切断・削除、配信者ごとの詳細設定パネル、ホットキーの割り当て・OS側への登録・競合検出)を、実際にXvfb上でクリック・キー入力を送って一通り動作確認済み。**
- **配信者アプリの「受け付けるリアクション」ON/OFF設定を、Xvfb上でチェックのON/OFF操作と設定の保存を確認済み。**
- 実行ファイルサイズ(Linux向けビルドで実測、1アプリあたり約9〜14MB)

一方で、以下はWindows実機でしか確認できません(この環境はLinuxで、pcwmp自体もWindows専用ソフトのため)。実際に使う前に必ず確認してください。

- pcwmpウィンドウの自動検出が実際のpcwmp上で正しく動くか
- 配信者アプリのオーバーレイが、フルスクリーン排他モードのゲームの上にちゃんと表示され続けるか
- リアクションバーが常時最前面かつクリックできる状態を保てるか(ゲームによってはオーバーレイ表示を許さないもの、アンチチートで弾かれるものがあります)
- 実際のルーター環境での動作(今回の設計では配信者アプリはポート開放不要・発信のみです)
- Windowsでのビルド・インストーラの動作、Windows Defender/SmartScreenの警告有無
- Windowsのディスプレイ拡大縮小(125%/150%等)環境での座標計算(この環境で見つかった不具合は修正しましたが、拡大縮小ありの実機での最終確認はできていません)
- ホットキー(グローバルショートカット)が実際にWindows上でOS全体に効くか(この環境ではLinux版のプラグイン経由でJS側のロジック・設定保存までは動作確認済みですが、実際にOSがキー入力をアプリ側の狙い通りに横取りするかはWindows実機でのみ確認できます)
- PeerCastを多重に開いた状態での「配信者名」による絞り込みが、実際のPCRPlayerの複数ウィンドウに対して正しく効くか
- OBSブラウザソース上での絵文字(特に矢印⬆⬇➡⬅・⏱)の見え方の修正が、実際のOBS(Chromium/CEF)で直っているか

## セットアップ・ビルド

各アプリのビルドには [Rust](https://www.rust-lang.org/ja) と [Tauri CLI](https://tauri.app/) が必要です。**Windows上でのビルドが必要です**(WebView2やWindows向けのビルドツールを使うため)。詳しい手順は [`WINDOWSでのテスト手順.md`](./WINDOWSでのテスト手順.md) を参照してください。概要は以下の通りです。

まず中継サーバーを起動します(配信者アプリ・視聴者アプリ共通で1つ立てておくだけでOKです)。

```bash
cd relay-server
npm install
PORT=39200 node server.js
```

本番運用時は、これを常時起動しておく小型VPS(または無料枠クラウド)に配置してください。従量課金の仕組みは使っていないので、Firebase等と違って「月末に上限で止まる」ことは起きません。

続けて、配信者アプリ・視聴者アプリをそれぞれビルドします。

```bash
cd broadcaster-app-tauri  # viewer-app-tauriも同様
npm install
npm run dev    # 開発中に動作確認する場合
npm run build  # 配布用の実行ファイル(.exe)を作る場合
```

`npm run build` を実行すると `src-tauri/target/release/ReaCast.exe`(視聴者アプリなら`ReaTap.exe`)が1つできます。**インストーラ形式ではなく、ダブルクリックでそのまま起動できる単体のexeファイル**です(`bundle.active`を`false`にしてあるため、インストール作業やインストーラ画面は出ません)。このファイル1つをそのまま配布・実行してもらえばOKです。

もしインストーラ形式(Start Menuへの登録・アンインストーラ付き)が欲しい場合は、`src-tauri/tauri.conf.json`の`bundle.active`を`true`に戻してから`npm run build`を実行すると、`src-tauri/target/release/bundle/nsis/`の中にインストーラができます。

配信者アプリ・視聴者アプリはどちらも `REACTION_RELAY_HOST` / `REACTION_RELAY_PORT` 環境変数で中継サーバーのアドレスをビルド時に指定します(未指定時はダミー値`relay.example.invalid`になるので、実際にデプロイしたアドレスに必ず書き換えてください)。

```bash
set REACTION_RELAY_HOST=<中継サーバーのIP or ホスト名>
set REACTION_RELAY_PORT=39200
npm run build
```

コード署名をしない場合、配布時にWindows SmartScreenの警告が出るのは既定の挙動です。

## 絵文字を追加・変更する

`viewer-app-tauri/frontend/shared/emoji-set.js` と `broadcaster-app-tauri/frontend/shared/emoji-set.js` の2箇所(内容は同じものを複製してあります)を編集してください。`id` は英数字と `_-` のみ(中継サーバー側のバリデーションと合わせる必要があります)。

## テストの実行

```bash
(cd viewer-app-tauri/src-tauri && cargo test)
(cd broadcaster-app-tauri/src-tauri && cargo test)
(cd relay-server && node test/e2e.test.js)
```
